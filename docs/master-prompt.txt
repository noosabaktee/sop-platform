### Ketentuan Database

1. Seluruh business records memiliki primary key.
2. Foreign key wajib digunakan.
3. Definisikan cardinality relasi yang benar.
4. Buat index untuk kolom yang sering digunakan.
5. Gunakan unique constraint.
6. Nilai uang menggunakan numeric/decimal.
7. Gunakan version atau row locking untuk transaksi bersamaan.
8. Gunakan transactions untuk operasi multi-tabel.
9. Gunakan soft delete hanya untuk entitas yang memang boleh dihapus secara logis.
10. Jangan menghapus transaksi final.
11. Jangan menyimpan data bisnis inti sebagai satu JSON blob generik.
12. JSONB hanya boleh dipakai untuk atribut fleksibel yang tepat.
13. Pastikan tenant/company isolation.
14. Status harus menggunakan domain enum/state machine yang konsisten.
15. Semua perubahan kritis mempunyai audit trail.
16. Lakukan validasi referential integrity.
17. Siapkan migration rollback yang masuk akal.
18. Pastikan migration dapat berjalan dari database kosong.

- Error code.
- Correlation ID.
- Permission error.

## 9.2 DILARANG DATA PALSU

Jangan menggunakan:

- Hardcoded array untuk data bisnis runtime.
- Random value untuk KPI.
- Data dummy di React component.
- Fake API response.
- `setTimeout()` sebagai simulasi request.
- Tombol Save yang hanya mengubah React state.
- Fake toast tanpa backend commit.
- Mock invoice yang tidak ada di database.
- Grafik yang tidak terhubung ke database.
- Simulasi approval tanpa update backend.
- Filter yang bekerja pada fixture sebagai pengganti server query.
- LocalStorage sebagai database transaksi.

LocalStorage hanya boleh digunakan untuk cache non-sensitif atau preferensi UI yang tidak kritis. Preferensi yang memang perlu berlaku lintas perangkat harus disimpan di backend.

Mock hanya boleh digunakan pada automated testing yang secara eksplisit terisolasi, bukan aplikasi runtime.

## 9.3 CRUD Harus Persisten

Contoh skenario:

1. User login.
2. User membuka Customers.
3. React memanggil Laravel API.
4. Laravel mengambil data PostgreSQL.
5. User menambahkan customer.
6. React mengirim POST request.
7. Laravel melakukan validation.
8. Laravel menyimpan customer ke PostgreSQL.
9. Laravel mengembalikan record yang berhasil disimpan.
10. React memperbarui tabel.
11. User refresh browser.
12. Customer masih ada.
13. User logout dan login kembali.
14. Customer tetap ada sesuai permission.

Lakukan prinsip ini pada seluruh modul.

## 9.4 Server-side Business Logic
